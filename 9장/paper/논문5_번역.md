## 1. 서론: 왜 하이퍼파라미터 튜닝이 중요한가?

### 1.1 랜덤 포레스트의 "블랙박스" 문제

랜덤 포레스트는 "적용하기 쉬운" 알고리즘으로 알려져 있지만, 실제로는 다수의 하이퍼파라미터를 가지며, 이들의 적절한 설정이 성능에 영향을 미칠 수 있다. 특히:

- **기본 설정이 항상 최적인가?** -> 대체로 좋지만, 항상 최적은 아니다.
- **어떤 파라미터를 튜닝해야 하는가?** -> mtry가 가장 중요하다.
- **얼마나 튜닝하면 충분한가?** -> 데이터에 따라 다르다.

### 1.2 연구 동기

기존 문헌에서는 개별 하이퍼파라미터에 대한 단편적인 분석은 있지만, **모든 파라미터를 종합적으로 분석하고 실용적 가이드라인을 제시**한 연구는 부족하였다. Probst 등은 이 공백을 메우기 위해 대규모 벤치마크 연구를 수행하였다.

## 3. 각 하이퍼파라미터의 영향 분석

### 3.1 mtry (max_features): 가장 중요한 파라미터

**이론적 배경**: Breiman(2001)의 핵심 부등식 PE* <= rho_bar * (1-s^2) / s^2에서, mtry는 rho_bar(상관관계)와 s(강도)를 동시에 결정한다.

**실험적 결과**:
```
mtry 변화에 따른 OOB 오류 (iris 데이터셋, 4개 특성):

mtry=1: OOB 오류 = 0.060
mtry=2: OOB 오류 = 0.040 (기본값 sqrt(4)=2)
mtry=3: OOB 오류 = 0.047
mtry=4: OOB 오류 = 0.053

-> mtry=2가 최적, 그러나 차이는 2% 이내
```

**핵심 발견**: mtry는 랜덤 포레스트에서 성능에 가장 큰 영향을 미치는 파라미터이다. 그러나 기본값(sqrt(p) 또는 p/3)이 대부분의 경우 좋은 출발점이 된다.

**튜닝 전략**:
```python
# Python에서의 mtry 튜닝
import numpy as np

p = X_train.shape[1]
mtry_candidates = [
    max(1, int(np.sqrt(p) * 0.5)),  # sqrt(p) / 2
    int(np.sqrt(p)),                  # sqrt(p) (기본값)
    max(1, int(np.sqrt(p) * 1.5)),  # sqrt(p) * 1.5
    max(1, int(np.sqrt(p) * 2)),    # sqrt(p) * 2
    int(p * 0.3),                     # p/3
    int(p * 0.5),                     # p/2
    p                                 # p (배깅과 동일)
]
```

### 3.2 min.node.size (min_samples_leaf)

**영향**: 리프 노드의 최소 크기를 설정하여 트리의 복잡도를 제어한다.

```
min.node.size 변화에 따른 효과:

min_samples_leaf=1:  가장 복잡한 트리. 분류의 기본값.
min_samples_leaf=5:  약간 단순한 트리. 회귀의 기본값.
min_samples_leaf=20: 상당히 단순한 트리. 과적합 감소.
min_samples_leaf=50: 매우 단순한 트리. 과소적합 가능성.
```

**핵심 발견**: min.node.size는 mtry 다음으로 중요한 파라미터이다. 기본값(분류: 1, 회귀: 5)이 대부분 적합하지만, 데이터가 노이즈가 많을 때는 값을 증가시키는 것이 유리할 수 있다.

### 3.3 sample.fraction (max_samples)

**영향**: 각 트리 학습에 사용할 데이터의 비율을 결정한다.

- 기본: 전체 데이터의 100% (복원추출)
- 서브샘플링: 예를 들어 63.2% (비복원추출, 부트스트랩의 유효 크기와 동일)

**핵심 발견**: 서브샘플링 비율은 대부분의 데이터셋에서 성능에 큰 영향을 미치지 않지만, 대규모 데이터셋에서는 학습 속도를 크게 향상시킬 수 있다.

### 3.4 num.trees (n_estimators)

**핵심 발견**: 트리 수는 "충분히 크기만 하면" 성능에 영향을 미치지 않는다.

```
트리 수에 따른 OOB 오류 수렴:

n_estimators=10:   불안정, OOB 변동 큼
n_estimators=100:  대부분 수렴
n_estimators=500:  안정적 수렴 (기본값)
n_estimators=1000: 추가 개선 미미
n_estimators=5000: 성능 동일, 계산 비용만 증가
```

**권장**: 500 이상이면 충분하다. OOB 오류의 수렴을 확인하여 결정한다.

## 4. 벤치마크 실험 결과

### 4.1 기본 설정 vs 튜닝

38개 분류 데이터셋과 21개 회귀 데이터셋에서의 결과:

**분류 (38개 데이터셋)**:
```
기본 설정 AUC:  0.892 (평균)
튜닝 후 AUC:   0.899 (평균)
개선폭:         0.007 (0.8%)

최대 개선:      0.05 (특정 데이터셋)
최소 개선:      0.00 (대부분의 데이터셋)
```

**회귀 (21개 데이터셋)**:
```
기본 설정 MSE:  (정규화)
튜닝 후 MSE:   약 3-5% 개선 (평균)
```

**핵심 발견**:
1. **기본 설정이 이미 좋다**: 대부분의 데이터셋에서 기본 설정의 성능이 양호하다.
2. **튜닝 효과는 미미하지만 일관적**: 평균적으로 작은 개선이지만, 거의 항상 개선 방향이다.
3. **특정 데이터셋에서는 큰 효과**: 일부 데이터셋(특히 고차원, 클래스 불균형)에서는 튜닝이 상당한 개선을 가져온다.

### 4.2 파라미터별 중요도 순위

```
파라미터 중요도 순위 (성능에 미치는 영향):

1위: mtry (max_features)         - 가장 영향이 큼
2위: min.node.size (min_samples_leaf)  - 두 번째로 영향이 큼
3위: sample.fraction (max_samples)     - 보통 영향이 적음
4위: num.trees (n_estimators)          - 충분히 크면 영향 없음
```

## 5. 튜닝 전략 비교

### 5.1 Grid Search (그리드 탐색)

미리 정의된 파라미터 조합을 모두 평가한다.

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    'max_features': ['sqrt', 'log2', 0.3, 0.5],
    'min_samples_leaf': [1, 2, 5, 10],
    'n_estimators': [100, 300, 500]
}

grid_search = GridSearchCV(
    RandomForestClassifier(), param_grid,
    cv=5, scoring='accuracy', n_jobs=-1
)
```

장점: 포괄적, 재현 가능
단점: 차원의 저주 - 파라미터가 많을수록 조합이 기하급수적으로 증가

### 5.2 Random Search (랜덤 탐색)

파라미터 공간에서 랜덤하게 조합을 선택한다.

```python
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import randint, uniform

param_dist = {
    'max_features': uniform(0.1, 0.9),
    'min_samples_leaf': randint(1, 20),
    'n_estimators': randint(100, 1000)
}

random_search = RandomizedSearchCV(
    RandomForestClassifier(), param_dist,
    n_iter=50, cv=5, scoring='accuracy', n_jobs=-1
)
```

장점: 그리드 탐색보다 효율적 (Bergstra & Bengio, 2012), 연속 공간 탐색 가능
단점: 최적해를 보장하지 않음

### 5.3 SMBO (Sequential Model-Based Optimization)

이전 평가 결과를 기반으로 다음 평가할 지점을 지능적으로 선택한다.

대표적 구현:
- **Bayesian Optimization** (BayesSearchCV from scikit-optimize)
- **TPE** (Tree-structured Parzen Estimator, Hyperopt)
- **BOHB** (Bayesian Optimization HyperBand)

장점: 가장 효율적 (적은 평가 횟수로 좋은 설정 발견)
단점: 구현이 복잡, 병렬화가 어려움

### 5.4 전략 비교 결과

```
동일한 계산 예산(100번 평가)에서의 최적 성능:

Grid Search:    0.895 AUC (제한된 조합만 평가)
Random Search:  0.898 AUC (더 넓은 공간 탐색)
SMBO:           0.901 AUC (지능적 탐색)
```

## 6. 특수 상황에서의 튜닝

### 6.1 고차원 데이터 (p >> n)

유전체 데이터 등 특성 수가 샘플 수보다 훨씬 많은 경우:
- **mtry를 기본값보다 작게**: sqrt(p)보다도 작은 값이 유리할 수 있다.
- **max_depth 제한 고려**: 매우 깊은 트리가 노이즈를 학습할 수 있다.

### 6.2 클래스 불균형

소수 클래스가 매우 적은 경우:
- **class_weight='balanced'**: 클래스 비율의 역수로 가중치를 부여한다.
- **sample.fraction + 층화 샘플링**: 부트스트랩 시 클래스 비율을 유지한다.

### 6.3 대규모 데이터셋

샘플 수가 수십만 이상인 경우:
- **sample.fraction을 줄인다**: 예를 들어 0.1~0.3으로 설정하여 학습 속도를 높인다.
- **min.node.size를 증가**: 불필요하게 깊은 트리를 방지한다.

## 7. 실용적 가이드라인 요약

### 7.1 추천 튜닝 워크플로우

```
Step 1: 기본 설정으로 기준선(baseline) 확립
        -> n_estimators=500, max_features='sqrt', min_samples_leaf=1

Step 2: ntree(n_estimators) 수렴 확인
        -> OOB 오류가 안정화되는지 확인

Step 3: mtry(max_features) 튜닝 (가장 중요!)
        -> [sqrt(p)/2, sqrt(p), sqrt(p)*2, p/3, p/2] 범위에서 탐색

Step 4: min.node.size(min_samples_leaf) 튜닝
        -> [1, 2, 5, 10, 20] 범위에서 탐색

Step 5: (선택) sample.fraction, max_depth 등 추가 튜닝
```

### 7.2 시간 제약별 권장사항

| 가용 시간 | 권장 전략 |
|:---|:---|
| 매우 제한적 | 기본 설정 사용 (이미 충분히 좋음) |
| 보통 | mtry만 5-7개 값으로 OOB 기반 튜닝 |
| 충분 | mtry + min.node.size 격자 탐색 |
| 풍부 | RandomizedSearchCV 또는 SMBO |

### 7.3 핵심 메시지

1. **mtry가 가장 중요하다**: 하나만 튜닝한다면 mtry를 튜닝하라.
2. **기본 설정을 신뢰하라**: 대부분의 경우 기본 설정이 좋은 출발점이다.
3. **과도한 튜닝을 피하라**: 튜닝에 의한 개선은 대체로 작다.
4. **OOB를 활용하라**: 교차검증 대신 OOB 오류로 빠르게 평가할 수 있다.
